Rust bukan bahasa berorientasi objek klasik, tetapi mendukung sebagian besar idenya dengan cara sendiri. Struct dan enum menyimpan data, `impl` menyediakan method, dan module mengatur enkapsulasi. Untuk polymorphism runtime, Rust memakai trait object seperti `Box<dyn Draw>`, bukan inheritance.

Di backend, trait object berguna saat handler perlu memilih implementasi pembayaran, notifier, atau storage pada runtime tanpa membuat kode bergantung pada tipe konkret.

## Urutan bab

1. [Karakteristik OOP](what-is-oo/) membahas object, encapsulation, inheritance, dan polymorphism.
2. [Trait object](trait-objects/) membahas `dyn`, `Box<dyn Trait>`, dynamic dispatch, dan dyn compatibility.
3. [State pattern](design-patterns/) membahas versi objek dan versi type-state.
4. [Studi kasus: registry pembayaran](studi-kasus/) memakai `Box<dyn PaymentMethod>` untuk Kasir Warung.

:::note[Kenapa begini?]
Trait object menukar fleksibilitas runtime dengan biaya dynamic dispatch. Generik menukar ukuran kode dan fleksibilitas koleksi dengan dispatch statis. Keduanya sah; pilih berdasarkan apakah tipe diketahui saat kompilasi dan apakah satu collection perlu menampung banyak tipe.
:::

:::tip[Tips]
Jangan memakai trait object hanya agar kode terlihat seperti OOP. Kalau semua tipe diketahui saat kompilasi, enum atau generik sering lebih sederhana dan lebih mudah diperiksa compiler.
:::
