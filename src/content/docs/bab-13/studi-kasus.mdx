CLI laporan di Bab 12 sudah membaca file transaksi dan menghitung rekap per menu. Sekarang kita menambahkan ringkasan transaksi yang memakai filter, map, fold, dan HashMap untuk mengelompokkan metode pembayaran.

<StudyCase title="Kasir Warung: rekap dengan iterator" intro="Mengubah daftar transaksi menjadi total lunas dan rekap per metode bayar.">
  <StudyCaseStep
    title="Proyeksi transaksi ke baris laporan"
    goal="Menyiapkan bentuk data ringkas yang mudah diproses iterator."
  >
    Data transaksi lengkap menyimpan menu, item, dan status pembayaran. Untuk laporan, kita hanya butuh beberapa field. Buat view ringkas agar fungsi rekap tidak bergantung pada seluruh struktur transaksi.

    ```rust
    #[derive(Debug, Clone)]
    pub struct TransaksiLaporan {
        pub pelanggan: String,
        pub metode: String,
        pub total: u32,
        pub lunas: bool,
    }
    ```

    Di kode lengkap, baris ini dihasilkan setelah transaksi dibayar. Total sudah dihitung oleh method transaksi, sehingga laporan tidak mengulang perhitungan subtotal.

    <Fragment slot="hint">
      View laporan bukan pengganti model transaksi. Ia hanya membawa field yang dibutuhkan laporan.
    </Fragment>

    <Fragment slot="solution">
      Dengan bentuk yang sempit, fungsi rekap lebih mudah dites dan tidak perlu mengetahui detail menu.
    </Fragment>
  </StudyCaseStep>

  <StudyCaseStep
    title="Filter status dan map total"
    goal="Menjumlahkan hanya transaksi yang lunas."
  >
    `filter` menyaring transaksi lunas, lalu `map` mengambil total dan `sum` menjumlahkannya.

    ```rust
    pub fn total_lunas(transaksi: &[TransaksiLaporan]) -> u32 {
        transaksi
            .iter()
            .filter(|t| t.lunas)
            .map(|t| t.total)
            .sum()
    }
    ```

    Rantai ini tidak membuat vector perantara. Setiap item diproses satu per satu sampai iterator habis.

    <Fragment slot="hint">
      `filter` menerima reference ke item, sehingga closure mendapat `&&TransaksiLaporan` saat dipanggil pada `iter`.
    </Fragment>

    <Fragment slot="solution">
      Hasilnya hanya total transaksi lunas. Transaksi yang belum dibayar tidak masuk hitungan.
    </Fragment>
  </StudyCaseStep>

  <StudyCaseStep
    title="Fold untuk akumulasi"
    goal="Menghitung total dan mengelompokkan metode bayar dengan satu nilai akumulator."
  >
    `fold` membawa state dari satu item ke item berikutnya. Bentuk ini berguna saat akumulasi bukan sekadar penjumlahan.

    ```rust
    pub fn total_lunas_fold(transaksi: &[TransaksiLaporan]) -> u32 {
        transaksi.iter().fold(0, |total, t| {
            if t.lunas {
                total + t.total
            } else {
                total
            }
        })
    }
    ```

    Fold juga bisa membangun `HashMap` berisi total per metode:

    ```rust
    pub fn total_per_metode(
        transaksi: &[TransaksiLaporan],
    ) -> HashMap<String, u32> {
        transaksi
            .iter()
            .filter(|t| t.lunas)
            .fold(HashMap::new(), |mut rekap, t| {
                *rekap.entry(t.metode.clone()).or_insert(0) += t.total;
                rekap
            })
    }
    ```

    <Fragment slot="hint">
      `entry(...).or_insert(0)` membuat nilai awal hanya jika metode belum ada, lalu referensi hasilnya bisa ditambah.
    </Fragment>

    <Fragment slot="solution">
      Satu pass menghasilkan total per metode tanpa vector tambahan.
    </Fragment>
  </StudyCaseStep>

  <StudyCaseStep
    title="Cetak ringkasan di CLI"
    goal="Mengurutkan hasil dan menampilkannya bersama laporan menu."
  >
    Urutkan kunci metode agar output stabil, lalu cetak total per metode dan total keseluruhan.

    ```rust
    pub fn cetak_ringkasan(transaksi: &[TransaksiLaporan]) {
        let per_metode = total_per_metode(transaksi);
        let mut metode: Vec<&String> = per_metode.keys().collect();
        metode.sort();

        println!("Ringkasan pembayaran:");
        for nama in metode {
            println!("{nama}: Rp{}", per_metode[nama]);
        }

        println!("Total lunas: Rp{}", total_lunas(transaksi));
    }
    ```

    <Fragment slot="hint">
      `keys()` menghasilkan iterator reference ke kunci. Setelah diurutkan, HashMap dipakai lagi untuk mengambil nilainya.
    </Fragment>

    <Fragment slot="solution">
      Laporan menu dari Bab 12 tetap berjalan. Ringkasan pembayaran menjadi bagian tambahan di stdout, sedangkan error tetap ke stderr.
    </Fragment>
  </StudyCaseStep>
</StudyCase>

## Keadaan setelah Bab 13

- `TransaksiLaporan` menjadi view ringkas untuk laporan pembayaran.
- `total_lunas` memakai `filter`, `map`, dan `sum`.
- `total_lunas_fold` memakai `fold` untuk akumulasi.
- `total_per_metode` memakai `filter` dan `fold` dengan `HashMap`.
- Output ringkasan memakai iterator untuk mengurutkan kunci dan mencetak hasil.
- Laporan menu dari Bab 12 dan error ke stderr tetap berlaku.
- Belum ada iterator yang mengembalikan hasil secara streaming ke pemanggil; itu latihan lanjutan.

:::note[Kalau di bahasa lain]
Pola ini mirip `filter` dan `reduce` di JavaScript, `filter` dan `sum` di Python, atau `stream().filter(...).mapToInt(...).sum()` di Java. Rust membuat adapter lazy dan memeriksa tipe item, sehingga hasil filter dan map harus cocok dengan metode berikutnya.
:::

:::tip[Tips]
Kalau akumulasi makin rumit, pertimbangkan loop eksplisit. `fold` yang berisi banyak cabang bisa lebih sulit dibaca daripada loop biasa.
:::
