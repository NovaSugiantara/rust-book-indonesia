## Config::build menerima iterator

`env::args` mengembalikan iterator, bukan slice. Alih-alih mengumpulkannya menjadi `Vec` lalu mengindeks, serahkan iterator itu langsung ke `Config::build`.

```rust
use std::env;
use std::process;

fn main() {
    let config = Config::build(env::args()).unwrap_or_else(|err| {
        eprintln!("Problem parsing arguments: {err}");
        process::exit(1);
    });

    if let Err(e) = run(config) {
        eprintln!("Application error: {e}");
        process::exit(1);
    }
}
```

Signature `build` berubah menjadi generic dengan bound iterator:

```rust
impl Config {
    fn build(mut args: impl Iterator<Item = String>) -> Result<Config, &'static str> {
        args.next();

        let query = match args.next() {
            Some(arg) => arg,
            None => return Err("tidak mendapat query"),
        };

        let file_path = match args.next() {
            Some(arg) => arg,
            None => return Err("tidak mendapat path file"),
        };

        Ok(Config { query, file_path })
    }
}
```

`args` harus mutable karena `next` mengubah posisi iterator. Panggilan `args.next()` pertama membuang nama program. Setelah itu, setiap `next` mengembalikan `Option<String>`.

Karena `build` mengambil kepemilikan `String` dari iterator, tidak ada `clone`. Nilai dipindahkan langsung ke field `Config`.

## Search dengan adapter

Versi Bab 12 memakai `Vec` mutable dan `push`. Versi iterator menyaring baris lalu mengumpulkannya:

<RustPlayground
  code={`fn search<'a>(query: &str, contents: &'a str) -> Vec<&'a str> {
    contents
        .lines()
        .filter(|line| line.contains(query))
        .collect()
}

fn main() {
    let contents = "Rust aman\\nBelajar Rust\\nBaris lain";
    let hasil = search("Rust", contents);

    for line in hasil {
        println!("{line}");
    }
}`}
  filename="src/lib.rs"
  label="search dengan filter dan collect"
/>

Tidak ada vector mutable perantara. `filter` menyimpan baris yang cocok, `collect` membangun vector hasil. Lifetime `'a` tetap menghubungkan hasil ke `contents`.

Kalau pemanggil tidak membutuhkan seluruh hasil sekaligus, `search` bisa mengembalikan iterator:

```rust
fn search<'a>(
    query: &'a str,
    contents: &'a str,
) -> impl Iterator<Item = &'a str> + 'a {
    contents
        .lines()
        .filter(move |line| line.contains(query))
}
```

Dengan bentuk ini, baris dicetak saat ditemukan, bukan setelah semua hasil dikumpulkan. Buku mencatat perubahan perilaku ini: sebelum perubahan, program menunggu semua hasil terkumpul; sesudahnya, hasil bisa dicetak selama iterasi. Test juga perlu disesuaikan karena hasilnya bukan `Vec` lagi.

## Loop atau iterator

Buku menyebut banyak programmer Rust lebih memilih gaya iterator karena fokus pada tujuan, bukan detail indeks dan vector sementara. Namun pilihan tetap bergantung pada keterbacaan. Loop eksplisit lebih jelas saat membutuhkan indeks, beberapa koleksi, atau kontrol alur yang kompleks.

:::note[Kalau di bahasa lain]
Di JavaScript, `array.filter(...).map(...)` langsung membangun array baru. Di Python, generator expression dan `map`/`filter` menghasilkan iterator lazy, sedangkan list comprehension membangun list. Rust memakai rantai adapter yang juga lazy, lalu `collect` menentukan collection tujuan. Perbedaan utamanya, tipe item dan lifetime iterator diperiksa compiler.
:::

:::tip[Tips]
Saat memindahkan loop ke iterator, jaga nama variabel dan urutan operasi tetap sama. Bandingkan output sebelum dan sesudah perubahan, jangan hanya mengandalkan test yang sudah ada.
:::
