Test endpoint memakai router axum langsung, tanpa listener TCP. Database test memakai SQLite in-memory dan migrasi yang sama dengan produksi.

<StudyCase title="Capstone: kualitas dan release" intro="Integration test, clippy, dan binary release.">
  <StudyCaseStep
    title="Siapkan state test"
    goal="Membuat database in-memory dan router yang bisa diuji."
  >
    ```rust
    async fn test_state() -> SharedState {
        let pool = SqlitePoolOptions::new()
            .max_connections(1)
            .connect("sqlite::memory:")
            .await
            .expect("database test");

        sqlx::migrate!("./migrations")
            .run(&pool)
            .await
            .expect("migrasi test");

        let (notif_tx, _notif_rx) = mpsc::channel(16);
        Arc::new(AppState { pool, notif_tx })
    }
    ```

    `max_connections(1)` penting untuk SQLite in-memory: setiap koneksi baru bisa mendapat database kosong yang berbeda.

    <Fragment slot="hint">
      Gunakan migrasi yang sama dengan produksi agar test tidak menguji skema yang berbeda.
    </Fragment>

    <Fragment slot="solution">
      Test memiliki state terisolasi dan tidak bergantung pada database lokal.
    </Fragment>
  </StudyCaseStep>

  <StudyCaseStep
    title="Uji alur endpoint"
    goal="Membuat menu, pesanan, pembayaran, status, dan laporan lewat router."
  >
    ```rust
    #[tokio::test]
    async fn alur_pesanan_bayar_status_dan_laporan() {
        let state = test_state().await;
        let app = router(state);

        create_menu(&app, "KOPI", "Kopi", 12_000).await;
        create_menu(&app, "ROTI", "Roti", 8_000).await;

        let id = create_order(
            &app,
            "Bu Sri",
            json!([{ "kode": "KOPI", "jumlah": 2 }, { "kode": "ROTI", "jumlah": 1 }]),
        )
        .await;

        let response = post_json(&app, &format!("/api/orders/{id}/pay"), json!({ "metode": "qris" })).await;
        assert_eq!(response.status(), StatusCode::OK);

        let response = patch_json(
            &app,
            &format!("/api/orders/{id}/status"),
            json!({ "status": "diproses" }),
        )
        .await;
        assert_eq!(response.status(), StatusCode::OK);

        let response = patch_json(
            &app,
            &format!("/api/orders/{id}/status"),
            json!({ "status": "selesai" }),
        )
        .await;
        assert_eq!(response.status(), StatusCode::OK);

        let response = app
            .oneshot(Request::builder().uri("/api/reports/daily").body(Body::empty()).unwrap())
            .await
            .unwrap();
        assert_eq!(response.status(), StatusCode::OK);
        assert_eq!(json_body(response).await["total"], 32_000);
    }
    ```

    Test ilegal juga penting: transisi `baru` ke `selesai` harus 409, dan metode pembayaran tidak dikenal harus 400.

    <Fragment slot="hint">
      `tower::ServiceExt::oneshot` memanggil router seperti request HTTP tanpa membuka socket.
    </Fragment>

    <Fragment slot="solution">
      Alur utama dan jalur error diuji di proses yang sama.
    </Fragment>
  </StudyCaseStep>

  <StudyCaseStep
    title="Jalankan pemeriksaan"


    <Fragment slot="hint">
      Jalankan clippy dengan `-D warnings` agar warning diperlakukan sebagai error di CI.
    </Fragment>

    <Fragment slot="solution">
      Kode lolos unit test, integration test, lint, dan build release.
    </Fragment>
  </StudyCaseStep>
</StudyCase>

:::note[Kalau di bahasa lain]
Express memakai Supertest, NestJS memakai TestingModule dan Supertest, Gin memakai httptest, Laravel memakai feature test, dan FastAPI memakai TestClient. Rust memakai router axum dengan `oneshot`, sehingga tidak perlu membuka port.
:::

:::tip[Tips]
Tambahkan test untuk setiap aturan transisi dan setiap status error yang penting. Test endpoint lebih cepat dan lebih stabil daripada menguji lewat browser.
:::
