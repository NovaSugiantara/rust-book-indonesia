Variabel Rust immutable secara default. Artinya, setelah sebuah nilai diikat ke nama, nilai itu tidak bisa diganti. Aturan ini terasa ketat saat pertama kali, tetapi membantu mencegah perubahan yang tidak disengaja.

Kamu tetap bisa membuat variabel mutable dengan menambahkan `mut`. Bedanya, perubahan nilai menjadi keputusan yang terlihat jelas di kode.

## Variabel immutable

Kode berikut sengaja salah. Variabel `x` diberi nilai 5, lalu dicoba diisi 6 tanpa `mut`.

<RustPlayground
  code={`fn main() {
    let x = 5;
    println!("The value of x is: {x}");
    x = 6;
    println!("The value of x is: {x}");
}`}
  expectError
  filename="src/main.rs"
  label="Contoh error mengubah variabel immutable"
/>

Compiler menolak dengan pesan `cannot assign twice to immutable variable`. Pesan itu menyebut baris pertama saat `x` diberi nilai dan baris saat kamu mencoba mengubahnya. Compiler juga biasanya menyarankan menambahkan `mut`.

## Variabel mutable

Tambahkan `mut` setelah `let`:

<RustPlayground
  code={`fn main() {
    let mut x = 5;
    println!("The value of x is: {x}");
    x = 6;
    println!("The value of x is: {x}");
}`}
  filename="src/main.rs"
  label="Mengubah nilai variabel mutable"
/>

Sekarang program mencetak 5 lalu 6. `mut` memberi izin mengubah nilai yang terikat ke `x`. Keyword ini juga memberi tahu pembaca kode bahwa nilai tersebut memang akan berubah.

:::note[Kenapa begini?]
Immutable sebagai default membuat kode lebih mudah dinalar. Kalau sebuah nilai tidak pernah berubah, kamu tidak perlu mencari semua tempat yang mungkin mengubahnya. Saat perubahan memang dibutuhkan, `mut` membuat niat itu eksplisit.
:::

## Konstanta

Konstanta mirip variabel immutable, tetapi ada beberapa perbedaan penting. Konstanta memakai keyword `const`, selalu immutable, dan tipenya wajib ditulis.

<RustPlayground
  code={`const THREE_HOURS_IN_SECONDS: u32 = 60 * 60 * 3;

fn main() {
    println!("Tiga jam sama dengan {THREE_HOURS_IN_SECONDS} detik.");
}`}
  filename="src/main.rs"
  label="Mendeklarasikan konstanta"
/>

Nama konstanta memakai huruf kapital semua dengan garis bawah antar kata. Nilainya harus berupa constant expression, yaitu ekspresi yang bisa dihitung compiler, bukan hasil yang baru diketahui saat program berjalan.

Konstanta bisa dideklarasikan di scope mana pun, termasuk scope global. Nilainya berlaku selama scope itu hidup. Ini berguna untuk angka yang dipakai di banyak tempat, misalnya batas maksimum atau tarif tetap.

:::tip[Tips]
Beri nama konstanta sesuai maknanya, bukan hanya nilainya. `TARIF_PAJAK` lebih mudah dipahami daripada `ANGKA_11`. Kalau nilainya berubah, kamu hanya perlu mengubah satu tempat.
:::

## Shadowing

Rust mengizinkan kamu mendeklarasikan variabel baru dengan nama yang sama. Variabel baru menutupi variabel lama. Ini disebut shadowing.

<RustPlayground
  code={`fn main() {
    let x = 5;

    let x = x + 1;

    {
        let x = x * 2;
        println!("The value of x in the inner scope is: {x}");
    }

    println!("The value of x is: {x}");
}`}
  filename="src/main.rs"
  label="Shadowing di dalam dan di luar scope"
/>

Program mencetak 12 di dalam blok, lalu 6 setelah blok selesai. Setiap `let x` membuat variabel baru. Variabel di blok dalam hanya berlaku sampai blok itu berakhir.

Shadowing berbeda dari `mut`. Dengan `mut`, kamu mengubah nilai pada variabel yang sama. Dengan shadowing, kamu membuat variabel baru dan bisa mengganti tipenya.

<RustPlayground
  code={`fn main() {
    let spaces = "   ";
    let spaces = spaces.len();

    println!("Jumlah spasi: {spaces}");
}`}
  filename="src/main.rs"
  label="Shadowing yang mengubah tipe"
/>

Variabel `spaces` pertama bertipe `&str`, yaitu teks. Variabel kedua bertipe `usize`, yaitu angka hasil `len()`. Nama yang sama dipakai ulang, tetapi tipe dan nilainya berbeda.

Sebaliknya, `mut` tidak mengizinkan perubahan tipe:

<RustPlayground
  code={`fn main() {
    let mut spaces = "   ";
    spaces = spaces.len();
}`}
  expectError
  filename="src/main.rs"
  label="Contoh error mut tidak bisa mengubah tipe"
/>

Compiler akan melaporkan `mismatched types`: variabel awalnya `&str`, lalu kamu mencoba mengisinya dengan `usize`.

:::caution[Hati-hati]
Jangan memakai shadowing hanya untuk menghindari nama yang jelas. Kalau dua nilai punya makna berbeda, nama berbeda biasanya lebih mudah dibaca. Shadowing paling berguna saat kamu mengubah bentuk nilai, misalnya dari teks menjadi angka.
:::
