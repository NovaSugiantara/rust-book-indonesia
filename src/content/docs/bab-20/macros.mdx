Macro menghasilkan atau mengubah kode saat kompilasi. Ia berbeda dari fungsi: macro bekerja pada sintaks, bisa menerima jumlah argumen bervariasi, dan bisa menghasilkan item baru seperti struct, impl, atau module.

## Macro versus fungsi

Fungsi menerima nilai dengan tipe dan jumlah parameter yang tetap. Macro menerima token sintaks dan mencocokkannya dengan aturan. Karena itu `println!` bisa menerima format dan argumen bervariasi, sedangkan fungsi biasa tidak bisa.

Macro berguna untuk menghilangkan boilerplate yang benar-benar berulang. Namun macro lebih sulit dibaca, di-debug, dan dianalisis tooling. Jangan mengganti fungsi biasa dengan macro tanpa alasan.

## macro_rules

`macro_rules!` mendefinisikan macro deklaratif dengan pattern dan ekspansi.

`$($x:expr),*` berarti nol atau lebih ekspresi dipisahkan koma. Bagian `$( ... )*` mengulang ekspansi untuk setiap ekspresi.

Kalau pemanggilan tidak cocok dengan aturan, compiler menolak:

Pesan `no rules expected 2` muncul karena macro mengharapkan koma di antara ekspresi. Macro error terjadi saat ekspansi, sebelum type checking normal.

## vec macro

Macro `vec!` di standard library kira-kira bekerja seperti ini:

```rust
#[macro_export]
macro_rules! vec {
    ( $( $x:expr ),* ) => {
        {
            let mut temp_vec = Vec::new();
            $(
                temp_vec.push($x);
            )*
            temp_vec
        }
    };
}
```

Ekspansi `vec![1, 2, 3]` menjadi kode yang membuat `Vec`, mendorong setiap nilai, lalu mengembalikan vector. Implementasi asli punya optimisasi tambahan, tetapi pola dasarnya sama.

## Procedural macro

Procedural macro bekerja pada `TokenStream` dan biasanya ditulis di crate terpisah dengan `proc-macro = true`. Ada tiga jenis:

- Custom derive, dipakai dengan `#[derive(Nama)]`.
- Attribute-like, dipakai sebagai atribut pada item.
- Function-like, dipanggil seperti fungsi, misalnya `sql!(...)`.

Contoh derive macro untuk trait `HelloMacro`:

```rust
use hello_macro::HelloMacro;
use hello_macro_derive::HelloMacro;

#[derive(HelloMacro)]
struct Pancakes;

fn main() {
    Pancakes::hello_macro();
}
```

Derive macro membaca nama struct dan menghasilkan implementasi trait. Untuk memproses sintaks, crate macro biasanya memakai `syn` dan `quote`:

```rust
use proc_macro::TokenStream;
use quote::quote;

#[proc_macro_derive(HelloMacro)]
pub fn hello_macro_derive(input: TokenStream) -> TokenStream {
    let ast = syn::parse(input).unwrap();
    let name = &ast.ident;

    let generated = quote! {
        impl HelloMacro for #name {
            fn hello_macro() {
                println!("Hello, Macro! My name is {}!", stringify!(#name));
            }
        }
    };

    generated.into()
}
```

Di backend, pola ini terlihat pada `#[derive(Serialize, Deserialize)]` dari serde. Derive menghasilkan kode serialisasi dan deserialisasi berdasarkan field struct, sehingga kamu tidak menulis konversi JSON secara manual. Attribute macro muncul pada framework web seperti `#[route(GET, "/")]`, sedangkan function-like macro muncul pada query builder atau DSL.

## Batas macro

Macro tidak memiliki informasi tipe seperti fungsi. Kesalahan bisa muncul pada kode hasil ekspansi, sehingga pesan error lebih sulit dibaca. Macro juga dapat membuat compile time bertambah dan IDE kurang memahami kode.

Kalau fungsi, generic, atau trait bisa menyelesaikan masalah, pilih itu. Gunakan macro saat sintaks pemanggilan atau generasi kode memang tidak bisa dicapai dengan abstraksi biasa.

:::note[Kalau di bahasa lain]
C dan C++ memakai preprocessor berbasis teks. Lisp dan Julia memiliki macro yang bekerja pada AST. Rust memakai `macro_rules!` untuk pattern token dan procedural macro untuk memanipulasi `TokenStream`. Derive macro Rust mirip code generator dekorator pada bahasa lain, tetapi berjalan saat kompilasi.
:::

:::tip[Tips]
Uji macro dengan `cargo expand` untuk melihat kode hasil ekspansi. Pesan error yang membingungkan sering berasal dari kode yang dihasilkan, bukan dari pemanggilan macro.
:::
