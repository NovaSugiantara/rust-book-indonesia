Async memungkinkan satu thread menangani banyak pekerjaan yang menunggu tanpa memblokir. Di server, ini berguna saat request menunggu database, layanan HTTP lain, atau antrean pesan. Selama satu future menunggu, runtime bisa menjalankan future lain.

Future di Rust bersifat lazy. Future tidak berjalan sampai di-await atau diserahkan ke runtime. Ini berbeda dari Promise JavaScript yang sudah mulai mengeksekusi pekerjaan saat dibuat.

## trpl di playground

Buku memakai crate `trpl` yang membungkus `futures` dan `tokio`. Rust Playground menyediakan `trpl` versi 0.3.0, jadi contoh di bab ini memakai API yang sama dengan buku. Kode `trpl` dipetakan ke Tokio di proyek nyata: `block_on` menjalankan future, `spawn_task` menyerupai `tokio::spawn`, dan `sleep` menyerupai `tokio::time::sleep`.

:::note[Kenapa begini?]
Async bukan thread. Task async dikelola runtime dan bisa berjalan di sejumlah thread terbatas. Keuntungannya muncul saat pekerjaan banyak menunggu, bukan saat pekerjaan menghabiskan CPU. Untuk CPU-bound, thread atau proses terpisah lebih tepat.
:::

:::tip[Tips]
Jangan menahan lock, melakukan `thread::sleep`, atau menjalankan komputasi panjang di dalam async tanpa await point. Semua itu bisa menghambat future lain di thread yang sama.
:::
