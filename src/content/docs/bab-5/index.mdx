Struct mengelompokkan beberapa nilai yang saling berhubungan menjadi satu tipe. Bedanya dengan tuple: setiap field punya nama. Nama field membuat kode lebih mudah dibaca dan lebih sulit tertukar.

Di backend, struct adalah bentuk paling dasar untuk memodelkan data: item menu, pesanan, transaksi, konfigurasi, dan response internal. Bab ini mulai dari struct sederhana, lalu berakhir dengan method dan studi kasus Kasir Warung.

## Urutan bab

1. [Mendefinisikan dan membuat instance](defining-structs/) membahas field, shorthand, update syntax, tuple struct, dan unit-like struct.
2. [Contoh program dengan struct](example-structs/) merefaktor program luas persegi panjang dan memakai Debug.
3. [Method](method-syntax/) membahas `impl`, `&self`, `&mut self`, dan associated function.
4. [Studi kasus: Kasir Warung](studi-kasus/) mengganti array terpisah dengan struct transaksi.

:::note[Kenapa begini?]
Data yang saling berhubungan sebaiknya disimpan bersama. Kalau lebar dan tinggi disimpan sebagai dua variabel terpisah, tidak ada yang mencegah kode menukar urutannya. Struct memberi nama dan tipe pada setiap bagian, sehingga kesalahan seperti itu lebih cepat terlihat.
:::

:::tip[Tips]
Mulai dari struct yang kecil. Tambahkan field hanya ketika ada kebutuhan nyata. Struct dengan sepuluh field sering kali merupakan tanda bahwa data itu sebaiknya dipecah menjadi beberapa tipe.
:::
