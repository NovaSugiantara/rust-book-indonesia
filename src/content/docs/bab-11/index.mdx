Test otomatis membuat perubahan kode bisa diperiksa tanpa menjalankan seluruh aplikasi secara manual. Rust menyertakan test runner di Cargo, jadi tidak perlu framework eksternal untuk memulai.

Di backend, test membantu menjaga aturan bisnis seperti validasi input, perhitungan total, dan pemetaan error ke response. Test tidak membuktikan program bebas bug, tetapi memberi jaring pengaman saat kode berubah.

## Urutan bab

1. [Menulis test](writing-tests/) membahas attribute `#[test]`, assertion, `should_panic`, dan test yang mengembalikan `Result`.
2. [Menjalankan test](running-tests/) membahas `cargo test`, filter, output, thread, dan test yang diabaikan.
3. [Organisasi test](test-organization/) membahas unit test di module dan integration test di folder `tests`.
4. [Studi kasus: Kasir Warung](studi-kasus/) menambahkan test untuk validasi, subtotal, dan pembayaran.

:::note[Kenapa begini?]
Test di Rust adalah fungsi biasa yang ditandai `#[test]`. `cargo test` mengompilasi kode test dan menjalankannya. Kalau sebuah test panic, test itu gagal. Ini alasan `assert_eq!`, `assert!`, dan `panic!` menjadi alat utama di test.
:::

:::tip[Tips]
Mulai dari satu test untuk perilaku yang paling penting. Test yang menguji terlalu banyak hal sekaligus sulit diketahui penyebab gagalnya.
:::
