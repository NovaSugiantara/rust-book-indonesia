Rust membedakan unit test dan integration test. Unit test tinggal dekat kode yang diuji. Integration test memakai crate dari luar, seperti pemakai library.

## Unit test

Unit test berada di module yang sama dengan kode dan biasanya dibungkus `#[cfg(test)]`.

```rust
pub fn add_two(a: u64) -> u64 {
    internal_adder(a, 2)
}

fn internal_adder(left: u64, right: u64) -> u64 {
    left + right
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn internal() {
        assert_eq!(internal_adder(2, 2), 4);
    }
}
```

Karena berada di dalam crate yang sama, unit test bisa menguji fungsi private seperti `internal_adder`. Integration test tidak bisa.

## Integration test

Integration test diletakkan di folder `tests` pada root package.

```text
adder/
├── Cargo.toml
├── src/
│   └── lib.rs
└── tests/
    └── integration_test.rs
```

Isi `tests/integration_test.rs`:

```rust
use adder::add_two;

#[test]
fn it_adds_two() {
    assert_eq!(add_two(2), 4);
}
```

Setiap file di `tests` dikompilasi sebagai crate terpisah. File itu harus mengimpor library dengan nama package, bukan memakai `crate::`.

Jalankan semua test:

```console
$ cargo test
running 1 test
test tests::internal ... ok

running 1 test
test it_adds_two ... ok
```

Jalankan hanya satu file integration test:

```console
$ cargo test --test integration_test
```

## Module bantu untuk test

Kalau beberapa integration test memakai helper yang sama, letakkan helper di `tests/common/mod.rs`.

```text
tests/
├── common/
│   └── mod.rs
└── integration_test.rs
```

```rust
mod common;

#[test]
fn it_adds_two() {
    common::setup();
    assert_eq!(adder::add_two(2), 4);
}
```

File di `tests/common/mod.rs` tidak dianggap integration test tersendiri karena berada di subfolder `common`.

Di proyek nyata, tiga assertion itu bisa menjadi tiga test terpisah agar kegagalan menunjukkan kasus yang tepat.

:::note[Kalau di bahasa lain]
Jest biasanya memisahkan file test di folder `__tests__` atau `*.test.js`. Go menaruh test di file `_test.go` pada package yang sama. PHPUnit punya folder `tests`, dan pytest menemukan file `test_*.py`. Rust membedakan unit test dalam crate dan integration test yang mengimpor crate seperti pengguna luar.
:::

:::tip[Tips]
Gunakan unit test untuk aturan internal dan edge case. Gunakan integration test untuk alur yang dilihat pemakai library atau API. Jangan menguji implementasi private dari integration test.
:::
