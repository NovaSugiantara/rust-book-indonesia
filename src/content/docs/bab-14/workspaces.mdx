Workspace adalah kumpulan package yang dikembangkan bersama. Semua package dalam workspace berbagi satu `Cargo.lock` dan satu folder `target`.

## Membuat workspace

Buat direktori, lalu tulis `Cargo.toml` di root tanpa bagian `[package]`:

```toml
[workspace]
members = ["adder"]
resolver = "3"
```

`members` berisi package yang ikut workspace. `resolver = "3"` memakai algoritma resolver terbaru yang disebut buku. Setelah itu, `cargo new` di dalam direktori workspace otomatis menambahkan package ke `members`.

```console
$ cargo new adder
     Created binary (application) `adder` package
      Adding `adder` as member of workspace
```

Struktur direktori menjadi:

```text
add/
├── Cargo.lock
├── Cargo.toml
├── adder/
│   ├── Cargo.toml
│   └── src/main.rs
└── target/
```

Hanya ada satu `Cargo.lock` dan satu `target` di root. Menjalankan `cargo build` dari dalam `adder` tetap menaruh hasil build di `add/target`. Ini menghindari kompilasi ulang dependency yang sama untuk setiap package.

## Menambah library

```console
$ cargo new add_one --lib
```

Tambahkan `add_one` ke `members`, lalu buat `adder` bergantung pada library itu lewat path:

```toml
[dependencies]
add_one = { path = "../add_one" }
```

Cargo tidak menganggap package dalam workspace otomatis saling bergantung. Dependency harus dinyatakan eksplisit.

`adder/src/main.rs` bisa memakai library:

```rust
fn main() {
    let angka = 10;
    println!("{angka} plus satu adalah {}", add_one::add_one(angka));
}
```

Jalankan package tertentu dengan `-p`:

```console
$ cargo run -p adder
```

Di playground tidak ada beberapa package, tetapi batas library dan binary bisa digambarkan dengan module:

## Satu lockfile, dependency tetap per package

Workspace menyatukan versi dependency yang kompatibel. Kalau `add_one` memakai `rand`, `adder` tidak otomatis bisa memakai `rand`. Setiap package tetap harus menulis dependency-nya sendiri.

Mencoba memakai crate yang tidak dideklarasikan menghasilkan error:

<RustPlayground
  code={`use crate_tidak_ada;

fn main() {
    println!("coba memakai crate yang tidak dideklarasikan");
}`}
  expectError
  filename="src/main.rs"
  label="Contoh error unresolved import crate yang tidak dideklarasikan"
/>

Pesan `unresolved import crate_tidak_ada` dan `no external crate` muncul karena crate itu tidak ada di dependencies package ini. Menambahkannya ke package lain dalam workspace tidak cukup. Di buku, error yang sama muncul saat `adder` memakai `rand` tanpa menulis dependency `rand` di `Cargo.toml`-nya.

Kalau dua package memakai versi dependency yang kompatibel, Cargo memakai satu versi. Kalau versinya tidak kompatibel, Cargo bisa menyelesaikan lebih dari satu versi agar masing-masing package tetap bekerja.

## Test dan publish

Dari root workspace, `cargo test` menjalankan test semua package. Untuk satu package:

```console
$ cargo test -p add_one
```

Publikasi juga dilakukan per package:

```console
$ cargo publish -p add_one
```

Setiap crate punya nama, versi, dan metadata sendiri. Workspace tidak membuat satu crate besar yang otomatis terpublikasi bersama.

:::note[Kalau di bahasa lain]
npm workspaces mengelola beberapa package JavaScript dalam satu repositori dengan dependency yang bisa di-hoist. Composer memakai `path` repository untuk package lokal. Go memakai `go work` dan file `go.work` untuk beberapa module. Rust memakai satu `Cargo.lock` dan satu `target`, dengan dependency path yang tetap ditulis per package.
:::

:::tip[Tips]
Pisahkan package ketika batasnya jelas, misalnya library inti, binary CLI, dan adapter database. Jangan memecah hanya karena jumlah file bertambah.
:::
