Sampai Bab 13, Cargo dipakai untuk membuat proyek, menambah dependency, menjalankan test, dan build. Bab ini membahas sisi lain Cargo: mengatur profil build, mendokumentasikan dan mempublikasikan crate, mengelola beberapa package dalam workspace, serta memasang binary dari crates.io.

Di backend, bagian ini terasa saat memecah aplikasi menjadi library dan binary, menyiapkan build release untuk deployment, atau membagikan library internal ke tim lain.

## Urutan bab

1. [Release profile](release-profiles/) membahas profil `dev` dan `release`, `opt-level`, dan kapan memakai masing-masing.
2. [Publikasi crate](publishing/) membahas dokumentasi, `pub use`, metadata, `cargo publish`, dan `cargo yank`.
3. [Workspace](workspaces/) membahas beberapa package dengan satu `Cargo.lock` dan satu folder `target`.
4. [cargo install](cargo-install/) membahas pemasangan binary dari crates.io.
5. [Custom command](custom-commands/) membahas binary `cargo-sesuatu` sebagai subcommand Cargo.
6. [Studi kasus: workspace Kasir Warung](studi-kasus/) memecah proyek menjadi `kasir-core` dan `kasir-cli`.

:::note[Kenapa begini?]
Cargo bukan hanya build tool. Ia mengatur metadata package, resolusi dependency, dokumentasi, distribusi, dan binary yang dipasang. Memahami batas package dan workspace membantu saat aplikasi tumbuh dari satu binary menjadi beberapa komponen.
:::

:::tip[Tips]
Jangan memecah proyek menjadi workspace terlalu awal. Mulai dari satu package, lalu pisahkan ketika ada batas yang jelas antara library dan binary atau ketika beberapa package benar-benar perlu berbagi dependency.
:::
