Concurrency memungkinkan beberapa bagian program berjalan bersamaan. Di backend, ini muncul saat server menangani banyak request, worker memproses antrean, atau beberapa tugas membaca cache dan database secara paralel.

Rust tidak menghilangkan kompleksitas concurrency. Yang Rust lakukan adalah menolak banyak kesalahan berbahaya saat kompilasi: data yang dipakai setelah dipindahkan, reference yang bisa hidup lebih lama dari pemiliknya, dan state bersama yang tidak aman dikirim antar thread. Setelah kode lolos compiler, kamu masih perlu memikirkan deadlock dan logika bisnis.

## Urutan bab

1. [Thread](threads/) membahas `thread::spawn`, `join`, dan closure `move`.
2. [Message passing](message-passing/) membahas channel `mpsc`, kepemilikan pesan, dan beberapa producer.
3. [Shared state](shared-state/) membahas `Mutex`, `Arc`, dan deadlock.
4. [Send dan Sync](send-sync/) membahas trait marker yang menentukan apa yang boleh menyeberang thread.
5. [Studi kasus: worker transaksi](studi-kasus/) memakai channel dan state bersama untuk memproses transaksi.

:::note[Kenapa begini?]
Rust memakai model thread 1:1 di standard library: satu thread bahasa berarti satu thread sistem operasi. Model lain tersedia lewat crate. Async di Bab 17 adalah pendekatan lain untuk concurrency, bukan pengganti otomatis untuk thread.
:::

:::tip[Tips]
Mulai dari batas data yang jelas. Kalau data berpindah antrean, pertimbangkan channel. Kalau banyak worker perlu membaca dan mengubah state yang sama, pertimbangkan `Arc<Mutex<T>>` dan ukur contention-nya.
:::
