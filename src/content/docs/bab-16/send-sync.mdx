`Send` dan `Sync` adalah trait marker di `std::marker`. Keduanya tidak punya method. Fungsinya memberi tahu compiler apakah sebuah tipe aman dipindahkan atau dirujuk antar thread.

## Send

`Send` berarti kepemilikan nilai bertipe itu boleh dipindahkan ke thread lain. Hampir semua tipe Rust mengimplementasikan `Send`, kecuali beberapa seperti `Rc<T>`.

`Rc<T>` tidak `Send` karena clone dan drop mengubah reference count tanpa sinkronisasi. Kalau dua thread mengubah count bersamaan, nilainya bisa salah.

## Sync

`Sync` berarti reference immutable ke tipe itu boleh dikirim ke thread lain. Secara definisi, `T` adalah `Sync` jika `&T` adalah `Send`.

Tipe yang tersusun seluruhnya dari bagian `Send` otomatis `Send`. Hal yang sama berlaku untuk `Sync`. Kamu tidak perlu mengimplementasikannya manual untuk tipe biasa.

## Yang tidak Send atau Sync

- `Rc<T>` tidak `Send` dan tidak `Sync`.
- `RefCell<T>` dan `Cell<T>` tidak `Sync` karena pengecekan borrow-nya tidak thread-safe.
- `Mutex<T>` adalah `Sync` jika `T: Send` dan bisa dipakai untuk akses bersama.
- `Arc<T>` adalah `Send` dan `Sync` jika `T` memenuhi syarat yang sesuai.

Mengirim `Rc<RefCell<T>>` ke thread ditolak compiler:

<RustPlayground

use std::rc::Rc;
use std::thread;

fn main() {
    let state = Rc::new(RefCell::new(0));

    thread::spawn(move || {
        *state.borrow_mut() += 1;
    })
    .join()
    .unwrap();
}`}

Pesan `Rc<RefCell<i32>> cannot be sent between threads safely` muncul karena `Rc` bukan `Send` dan `RefCell` bukan `Sync`. Gantinya adalah `Arc<Mutex<T>>`.

## Implementasi manual

Tipe yang seluruh bagiannya aman otomatis mendapat `Send` dan `Sync`. Kalau kamu membuat tipe concurrency baru dari bagian yang tidak aman, implementasi manual membutuhkan `unsafe` dan tanggung jawab membuktikan invariant. Bab ini tidak membahasnya lebih jauh; buku merujuk ke Rustonomicon.

## Di backend

State aplikasi yang dibagi ke handler biasanya harus `Send + Sync + 'static` agar bisa dipakai lintas thread. Itu sebabnya `Rc<RefCell<T>>` tidak cocok untuk state server, sedangkan `Arc<Mutex<T>>` atau `Arc<RwLock<T>>` bisa.

Trait bound ini juga muncul di error framework. Kalau compiler mengeluh state tidak `Send` atau `Sync`, biasanya ada `Rc`, `RefCell`, atau reference dengan umur yang salah di dalamnya.

:::note[Kalau di bahasa lain]
Go tidak memakai trait marker seperti `Send` dan `Sync`; compiler tidak memeriksa apakah struct berisi pointer yang tidak aman untuk goroutine. Node.js worker tidak berbagi heap JavaScript, sehingga state harus dikirim lewat pesan atau `SharedArrayBuffer`. Python tidak memeriksa keamanan thread pada level tipe; programmer memakai lock dan dokumentasi. Rust memindahkan sebagian pemeriksaan itu ke sistem tipe.
:::

:::tip[Tips]
Saat error menyebut `Send` atau `Sync`, cari tipe yang tidak memenuhi di dalam struct. Biasanya `Rc`, `RefCell`, atau `*const T`. Ganti dengan primitif yang sesuai, jangan menambahkan `unsafe impl` tanpa alasan kuat.
:::
