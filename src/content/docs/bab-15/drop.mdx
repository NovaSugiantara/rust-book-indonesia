Trait `Drop` memungkinkan kode cleanup dijalankan saat nilai keluar dari scope. Compiler menyisipkan pemanggilan ini otomatis, sehingga sumber daya seperti file, koneksi, atau lock bisa dilepas tanpa pemanggilan manual di setiap jalur.

## Implementasi Drop

<RustPlayground
  code={`struct CustomSmartPointer {
    data: String,
}

impl Drop for CustomSmartPointer {
    fn drop(&mut self) {
        println!("Menghapus CustomSmartPointer dengan data {}", self.data);
    }
}

fn main() {
    let c = CustomSmartPointer {
        data: String::from("pertama"),
    };
    let d = CustomSmartPointer {
        data: String::from("kedua"),
    };

    println!("CustomSmartPointer dibuat");
}`}
  filename="src/main.rs"
  label="Drop dijalankan saat nilai keluar dari scope"
/>

Output menunjukkan `d` di-drop sebelum `c`, karena variabel di-drop dalam urutan kebalikan dari pembuatannya. `Drop` sudah ada di prelude, jadi tidak perlu `use`.

## Tidak bisa memanggil drop secara manual

Method `drop` tidak boleh dipanggil langsung. Kalau dipanggil, nilai akan dibersihkan dua kali: sekali oleh pemanggilan manual dan sekali otomatis saat scope berakhir.

<RustPlayground
  code={`struct CustomSmartPointer;

impl Drop for CustomSmartPointer {
    fn drop(&mut self) {
        println!("cleanup");
    }
}

fn main() {
    let c = CustomSmartPointer;
    c.drop();
}`}
  expectError
  filename="src/main.rs"
  label="Contoh error memanggil drop secara eksplisit"
/>

Pesan `explicit destructor calls not allowed` muncul karena Rust melarang pemanggilan `Drop::drop` langsung. Ini mencegah double free.

## Drop lebih awal dengan std::mem::drop

Kalau nilai perlu dibersihkan sebelum akhir scope, gunakan fungsi `std::mem::drop`, yang juga tersedia sebagai `drop` di prelude.

<RustPlayground
  code={`struct CustomSmartPointer {
    data: String,
}

impl Drop for CustomSmartPointer {
    fn drop(&mut self) {
        println!("Menghapus {}", self.data);
    }
}

fn main() {
    let c = CustomSmartPointer {
        data: String::from("sebelum akhir main"),
    };

    println!("Dibuat");
    drop(c);
    println!("Setelah drop");
}`}
  filename="src/main.rs"
  label="std::mem::drop untuk cleanup lebih awal"
/>

Pesan cleanup muncul di antara `Dibuat` dan `Setelah drop`. Setelah `drop(c)`, `c` tidak boleh dipakai lagi karena kepemilikannya sudah diambil fungsi `drop`.

## Kapan Drop berguna

`Drop` berguna untuk melepas resource yang harus segera dikembalikan, misalnya:

- menutup file atau koneksi,
- melepas lock,
- mengembalikan koneksi ke pool,
- mencatat metrik saat guard selesai.

Di backend, guard sering membawa referensi ke resource dan melakukan cleanup saat scope selesai. Karena `Drop` berjalan otomatis, jalur error yang keluar lebih awal tetap menjalankan cleanup selama nilai benar-benar di-drop.

`Drop` tidak boleh panic. Panic saat panic lain sedang berlangsung dapat menghentikan program. Bersihkan resource dengan operasi yang tidak melempar panic tak terkendali.

:::note[Kalau di bahasa lain]
Di JavaScript dan Python, cleanup sering bergantung pada garbage collector atau blok `try/finally`; Python juga punya context manager. Di Go, `defer` menjadwalkan pemanggilan saat fungsi selesai. Rust menjalankan `Drop` saat nilai keluar dari scope, sehingga cleanup mengikuti ownership dan tidak perlu ditulis di setiap jalur keluar.
:::

:::tip[Tips]
Jangan menaruh logika bisnis penting di `Drop`. Buat cleanup yang singkat dan tidak bergantung pada state yang mungkin sudah tidak valid. Untuk operasi yang bisa gagal, sediakan method eksplisit sebelum drop.
:::
