Bab ini adalah inti Rust. Kalau kamu hanya membawa satu konsep dari bahasa ini ke pekerjaan backend, bawa aturan ownership dan borrow. Aturan ini menjelaskan kenapa Rust bisa mengelola memory tanpa garbage collector, kenapa data berpindah kepemilikan, dan kenapa compiler menolak beberapa program yang terlihat wajar di bahasa lain.

Untuk pembaca yang datang dari JavaScript, Go, atau Python, bagian tersulit biasanya bukan sintaks. Bagian tersulit adalah membiasakan diri bahwa sebuah nilai punya satu pemilik, dan bahwa meminjam nilai punya aturan. Di backend, aturan ini muncul saat request masuk, saat data dimasukkan ke cache, saat worker mengambil antrean, dan saat response dibentuk.

## Tiga aturan

1. Setiap nilai di Rust punya satu owner.
2. Hanya boleh ada satu owner pada satu waktu.
3. Saat owner keluar dari scope, nilainya di-drop.

Aturan ini diperiksa compiler. Tidak ada runtime garbage collector yang berjalan di belakang layar.

## Urutan bab

1. [Apa itu ownership](what-is-ownership/) membahas scope, heap, move, clone, dan Copy.
2. [Reference dan borrowing](references-borrowing/) membahas `&`, `&mut`, dan aturan pinjaman.
3. [Slice](slices/) membahas `&str` dan `&[T]`.
4. [Studi kasus: Kasir Warung](studi-kasus/) memakai borrow dan slice pada struk.

:::note[Kenapa begini?]
Compiler memeriksa ownership saat kompilasi, bukan saat program berjalan. Karena itu, bug seperti use-after-free atau double free tidak perlu ditemukan lewat test produksi. Compiler menolak kode yang melanggar aturan sebelum binary dibuat.
:::

:::tip[Tips]
Saat borrow checker menolak kode, jangan langsung menambahkan `.clone()`. Baca dulu nilai mana yang dipinjam, siapa pemiliknya, dan berapa lama pinjaman itu dipakai. Clone adalah pilihan terakhir yang disengaja, bukan solusi otomatis.
:::
