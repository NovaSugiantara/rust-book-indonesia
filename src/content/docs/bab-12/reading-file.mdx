Setelah path file didapat dari argumen, program perlu membaca isinya. `std::fs::read_to_string` membuka file dan mengembalikan seluruh isinya sebagai `String`.

## Menyiapkan file contoh

Buat `poem.txt` di root proyek. Puisi Emily Dickinson dipakai di buku karena punya beberapa baris dengan kata berulang.

```text
I'm nobody! Who are you?
Are you nobody, too?
Then there's a pair of us - don't tell!
They'd banish us, you know.

How dreary to be somebody!
How public, like a frog
To tell your name the livelong day
To an admiring bog!
```

## Membaca isi file

Tambahkan `use std::fs;` lalu panggil `fs::read_to_string`:

```rust
use std::env;
use std::fs;

fn main() {
    let args: Vec<String> = env::args().collect();
    let query = &args[1];
    let file_path = &args[2];

    println!("Mencari {query}");
    println!("Di file {file_path}");

    let contents = fs::read_to_string(file_path)
        .expect("file seharusnya bisa dibaca");

    println!("Isi file:\n{contents}");
}
```

`fs::read_to_string` mengembalikan `std::io::Result<String>`. Tipe itu adalah alias `Result<String, std::io::Error>`. File bisa gagal dibaca karena tidak ada, tidak punya izin, atau path bukan file teks yang valid.

`expect` membuka nilai `Ok` dan menghentikan program dengan pesan jika hasilnya `Err`. Untuk eksplorasi awal ini cukup, tetapi pesan `expect` yang sama dipakai untuk semua penyebab kegagalan. Refactoring berikutnya akan menggantinya dengan penanganan error yang lebih informatif.

## Result bukan String

Hasil `read_to_string` tidak bisa langsung dipakai sebagai teks. Ia harus dibuka dengan `expect`, `unwrap`, `match`, atau operator `?`.

Pesan `std::io::Error doesn't implement std::fmt::Display` versi `Result` muncul karena `println!` dengan `{}` membutuhkan `Display`, sedangkan `Result` tidak mengimplementasikannya. Buka hasilnya lebih dulu, misalnya dengan `expect` atau `match`.

## Memakai isi file

Setelah dibuka, `String` bisa dipecah menjadi baris dengan `lines`. Contoh berikut memakai teks yang disimpan langsung agar bisa dijalankan di playground. Di program asli, teks yang sama berasal dari `fs::read_to_string`.

<RustPlayground
  code={`fn main() {
    let contents = "I'm nobody! Who are you?\\nAre you nobody, too?\\nThen there's a pair of us - don't tell!\\n";

    for line in contents.lines() {
        println!("{line}");
    }

    println!("Jumlah baris: {}", contents.lines().count());
}`}
  filename="src/main.rs"
  label="Memecah isi file menjadi baris"
/>

`lines` memisahkan teks pada newline dan membuang `\r` di akhir baris. Ini nyaman untuk file teks, tetapi bukan parser format biner.

:::note[Kalau di bahasa lain]
Node.js memakai `fs.readFileSync(path, "utf8")` dan mengembalikan string atau melempar exception. Go memakai `os.ReadFile` yang mengembalikan `[]byte` dan `error`. PHP memakai `file_get_contents`. Rust mengembalikan `Result<String, io::Error>`, sehingga kegagalan membaca file adalah nilai yang harus ditangani, bukan exception tersembunyi.
:::

:::tip[Tips]
Baca file setelah argumen tervalidasi. Kalau path belum tentu ada, tangani `Err` dan tampilkan path yang gagal dibaca agar pengguna tahu apa yang harus diperbaiki.
:::
