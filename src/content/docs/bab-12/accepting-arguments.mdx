Program CLI menerima input pertama dari command line. Di Rust, `std::env::args` mengembalikan iterator berisi argumen yang dipakai saat program dijalankan. Iterator itu diubah menjadi `Vec<String>` dengan `collect`.

## Membuat proyek

```console
$ cargo new minigrep
     Created binary (application) `minigrep` project
$ cd minigrep
```

Binary yang dihasilkan belum membaca argumen. Tambahkan `use std::env;` dan kumpulkan argumen di `main`:

```rust
use std::env;

fn main() {
    let args: Vec<String> = env::args().collect();
    println!("{args:?}");
}
```

Jalankan dengan dua argumen:

```console
$ cargo run -- test sample.txt
["target/debug/minigrep", "test", "sample.txt"]
```

Elemen pertama adalah path binary, bukan argumen pertama yang diketik pengguna. Ini mengikuti perilaku daftar argumen di C dan memungkinkan program mengetahui nama atau alias yang dipakai untuk memanggilnya.

## Anotasi tipe pada collect

`collect` bisa menghasilkan banyak jenis collection, sehingga compiler tidak selalu bisa menyimpulkan tipe yang dimaksud. Anotasi `Vec<String>` atau tipe pada variabel diperlukan.

Tanpa anotasi, compiler tidak tahu collection apa yang diminta:

<RustPlayground
  code={`use std::env;

fn main() {
    let args = env::args().collect();
    println!("{}", args[1]);
}`}
  expectError
  filename="src/main.rs"
  label="Contoh error collect tanpa anotasi tipe"
/>

Pesan `type annotations needed` muncul karena `collect` hanya tahu bahwa hasilnya adalah collection, bukan collection apa. Tambahkan `Vec<String>` untuk memperjelas.

## Menyimpan argumen ke variabel

Setelah argumen terkumpul, ambil query di indeks 1 dan path file di indeks 2:

<RustPlayground
  code={`fn main() {
    let args = vec![
        String::from("target/debug/minigrep"),
        String::from("test"),
        String::from("sample.txt"),
    ];

    let query = &args[1];
    let file_path = &args[2];

    println!("Mencari {query}");
    println!("Di file {file_path}");
}`}
  filename="src/main.rs"
  label="Mengambil query dan path dari Vec argumen"
/>

Di program asli, `args` berasal dari `env::args().collect()`. Playground tidak bisa menerima argumen command line dari pemanggil, jadi contoh ini menyusun vector yang sama secara manual.

## Bahaya indeks di luar batas

Mengakses `args[2]` saat hanya ada satu elemen membuat program panic. Kode berikut gagal saat dijalankan, bukan saat dikompilasi:

```rust
use std::env;

fn main() {
    let args: Vec<String> = env::args().collect();
    let query = &args[1];
    println!("{query}");
}
```

Kalau dijalankan tanpa argumen, muncul `index out of bounds: the len is 1 but the index is 1`. Pesan ini ditujukan untuk programmer, bukan pengguna CLI. Bab ini akan menggantinya dengan `Result` dan pesan yang jelas saat membahas refactoring.

## Argumen dengan Unicode tidak valid

`env::args` panic kalau ada argumen yang bukan Unicode valid. Untuk menerima argumen semacam itu, gunakan `env::args_os`, yang menghasilkan `OsString`. Contoh di bab ini memakai `args` agar kode lebih sederhana.

:::note[Kalau di bahasa lain]
Di Node.js, argumen ada di `process.argv` dan dua elemen pertama adalah path Node serta path skrip. Di Go, `os.Args` juga menyertakan nama program di indeks 0. Di PHP, `$argv[0]` adalah nama skrip. Rust mengikuti pola yang sama: indeks 0 adalah nama program, argumen pengguna mulai dari indeks 1.
:::

:::tip[Tips]
Perlakukan indeks 0 sebagai nama program. Jangan memakai `args[1]` tanpa memeriksa panjang vector lebih dulu, karena input pengguna tidak bisa dipercaya.
:::
