Bab ini menggabungkan modul, collection, error handling, trait, lifetime, dan test menjadi satu program CLI. Proyek utamanya adalah `minigrep`, versi sederhana dari `grep`: menerima query dan path file, membaca file, lalu mencetak baris yang cocok.

Bagi backend developer, pola ini dekat dengan pekerjaan sehari-hari. CLI impor data, skrip migrasi, dan alat operasional membaca argumen, membuka file, menangani error, dan menulis hasil ke stdout. Semua bagian itu muncul di bab ini.

## Urutan bab

1. [Menerima argumen](accepting-arguments/) membahas `env::args`, `Vec<String>`, dan membaca argumen program.
2. [Membaca file](reading-file/) membahas `fs::read_to_string` dan `io::Result`.
3. [Refactoring dan error](refactoring/) membahas `Config::build`, `Result`, `run`, dan pemisahan `main.rs` dengan `lib.rs`.
4. [TDD pencarian](tdd/) membahas test yang gagal lebih dulu lalu implementasi `search`.
5. [Environment variable](environment-variables/) membahas `env::var` dan pencarian tanpa membedakan huruf besar kecil.
6. [Standard error](stderr/) membahas `eprintln!`, stdout, dan exit status.
7. [Studi kasus: Kasir Warung](studi-kasus/) membuat CLI laporan harian dari file transaksi.

:::note[Kenapa begini?]
Program CLI yang baik memisahkan tiga hal: konfigurasi dari argumen, logika di library, dan penanganan error di `main`. Pemisahan ini membuat logika bisa dites tanpa menjalankan binary, persis alasan `main.rs` dan `lib.rs` dipisahkan di bab ini.
:::

:::tip[Tips]
Jalankan program setelah setiap perubahan kecil. CLI bergantung pada input dari luar, jadi kesalahan argumen atau path lebih cepat terlihat saat program benar-benar dijalankan.
:::
