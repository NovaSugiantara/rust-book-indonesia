Path panjang membuat kode sulit dibaca. `use` membawa path ke scope sehingga kamu bisa memakai nama yang lebih pendek.

## Use module

Daripada menulis path penuh setiap kali, impor module-nya.

<RustPlayground
  code={`mod front_of_house {
    pub mod hosting {
        pub fn add_to_waitlist() {
            println!("Tamu ditambahkan");
        }
    }
}

use crate::front_of_house::hosting;

fn main() {
    hosting::add_to_waitlist();
}`}
  filename="src/main.rs"
  label="Use untuk module"
/>

`use` hanya membuat shortcut. Ia tidak mengubah visibilitas. Kalau item private, `use` tidak akan menyelamatkan akses.

## Scope use

`use` berlaku di scope tempat ia ditulis. Module lain tidak otomatis melihat shortcut itu.

<RustPlayground
  code={`mod front_of_house {
    pub mod hosting {
        pub fn add_to_waitlist() {}
    }
}

use crate::front_of_house::hosting;

mod customer {
    pub fn eat_at_restaurant() {
        hosting::add_to_waitlist();
    }
}

fn main() {}`}
  expectError
  filename="src/main.rs"
  label="Contoh error use tidak terlihat di module lain"
/>

Compiler menyebut `cannot find module or crate hosting in this scope`. Tambahkan `use crate::front_of_house::hosting;` di dalam module `customer`, atau gunakan path lengkap.

## Use item langsung

Kamu bisa mengimpor fungsi atau tipe langsung, bukan hanya module.

<RustPlayground
  code={`mod front_of_house {
    pub mod hosting {
        pub fn add_to_waitlist() {
            println!("Tamu ditambahkan");
        }
    }
}

use crate::front_of_house::hosting::add_to_waitlist;

fn main() {
    add_to_waitlist();
}`}
  filename="src/main.rs"
  label="Use untuk fungsi"
/>

Untuk fungsi, mengimpor module induk sering lebih jelas karena pemanggil masih melihat asal fungsi. Untuk tipe seperti `HashMap`, mengimpor tipe langsung adalah kebiasaan umum.

## Alias

Kalau dua item punya nama sama, gunakan `as` untuk memberi nama berbeda.

<RustPlayground
  code={`use std::fmt::Result;
use std::io::Result as IoResult;

fn tampilkan() -> Result {
    Ok(())
}

fn baca() -> IoResult<()> {
    Ok(())
}

fn main() {
    let _ = tampilkan();
    let _ = baca();
}`}
  filename="src/main.rs"
  label="Alias dengan as"
/>

Alias juga berguna saat nama asli terlalu panjang atau terlalu umum.

## pub use

`pub use` membuat re-export. Item yang diimpor menjadi bagian dari API module saat ini.

<RustPlayground
  code={`mod front_of_house {
    pub mod hosting {
        pub fn add_to_waitlist() {
            println!("Tamu ditambahkan");
        }
    }
}

pub use crate::front_of_house::hosting;

fn main() {
    hosting::add_to_waitlist();
}`}
  filename="src/main.rs"
  label="Re-export dengan pub use"
/>

Dalam library, `pub use` sering dipakai untuk menyusun API yang nyaman tanpa membocorkan struktur module internal.

## Glob

Glob `*` mengimpor semua item public dari sebuah module.

<RustPlayground
  code={`use std::collections::*;

fn main() {
    let mut nilai = HashMap::new();
    nilai.insert("Bir", 10);

    let daftar: Vec<&str> = vec!["satu", "dua"];

    println!("{nilai:?} {daftar:?}");
}`}
  filename="src/main.rs"
  label="Glob import"
/>

Glob berguna untuk prelude atau test, tetapi untuk kode aplikasi biasanya terlalu luas. Kamu sulit melihat asal nama dan konflik antar import.

:::note[Kalau di bahasa lain]
`use` mirip `import` di JavaScript atau Python, `use` di PHP, dan `import` di Go. Bedanya, `use` di Rust tidak mengubah visibilitas dan hanya berlaku di scope tempat ia ditulis. `pub use` mirip re-export dari barrel file JavaScript.
:::

:::tip[Tips]
Impor module induk untuk fungsi, dan impor tipe langsung untuk struct atau enum yang sering dipakai. Hindari glob di kode aplikasi kecuali ada alasan yang jelas.
:::
