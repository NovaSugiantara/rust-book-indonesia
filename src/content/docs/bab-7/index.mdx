Sampai Bab 6, semua kode ada di satu file atau satu crate kecil. Proyek backend tidak bertahan lama dengan cara itu. Kamu perlu memisahkan menu, transaksi, laporan, konfigurasi, dan handler agar batas tanggung jawabnya jelas.

Bab ini membahas sistem module Rust: package, crate, module, path, `use`, dan `pub`. Setelah bab ini, Kasir Warung akan dipecah menjadi library dan binary yang bisa dijalankan dengan `cargo run`.

## Urutan bab

1. [Package dan crate](packages-crates/) membedakan package, binary crate, library crate, dan crate root.
2. [Module](modules/) membahas `mod`, nested module, privacy, dan module tree.
3. [Path](paths/) membahas `crate`, `super`, `self`, dan aturan `pub`.
4. [Use](use/) membahas shortcut path, alias, glob, dan `pub use`.
5. [Memisahkan file](files/) membahas `mod` yang menunjuk ke file dan folder.
6. [Studi kasus: Kasir Warung](studi-kasus/) memecah proyek menjadi library dan binary.

:::note[Kenapa begini?]
Module bukan sekadar folder. Module adalah batas privasi. Kode di dalam module private terhadap module induk secara default. Compiler memakai batas itu untuk mencegah bagian lain mengambil detail implementasi yang seharusnya tidak stabil.
:::

:::tip[Tips]
Mulai dari batas domain, bukan dari jenis file. `menu`, `transaksi`, dan `laporan` lebih mudah dijelaskan daripada `utils`, `helpers`, dan `misc`.
:::
