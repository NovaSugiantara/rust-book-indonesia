Generic memungkinkan satu definisi dipakai untuk banyak tipe konkret. Tanpa generic, kamu akan menulis fungsi yang isinya sama berulang kali untuk `i32`, `f64`, `char`, dan tipe lain.

## Duplikasi tanpa generic

Fungsi `largest_i32` dan `largest_char` isinya sama. Hanya tipe elemennya berbeda.

<RustPlayground
  code={`fn largest_i32(list: &[i32]) -> &i32 {
    let mut largest = &list[0];

    for item in list {
        if item > largest {
            largest = item;
        }
    }

    largest
}

fn largest_char(list: &[char]) -> &char {
    let mut largest = &list[0];

    for item in list {
        if item > largest {
            largest = item;
        }
    }

    largest
}

fn main() {
    let numbers = vec![34, 50, 25, 100, 65];
    let chars = vec!['y', 'm', 'a', 'q'];

    println!("{} {}", largest_i32(&numbers), largest_char(&chars));
}`}
  filename="src/main.rs"
  label="Dua fungsi dengan logika yang sama"
/>

## Fungsi generik

Kita bisa mengganti tipe konkret dengan parameter `T`:

<RustPlayground
  code={`fn largest<T: PartialOrd>(list: &[T]) -> &T {
    let mut largest = &list[0];

    for item in list {
        if item > largest {
            largest = item;
        }
    }

    largest
}

fn main() {
    let numbers = vec![34, 50, 25, 100, 65];
    let chars = vec!['y', 'm', 'a', 'q'];

    println!("{} {}", largest(&numbers), largest(&chars));
}`}
  filename="src/main.rs"
  label="Fungsi largest generik dengan trait bound"
/>

`T: PartialOrd` adalah trait bound. Tanpa bound itu, compiler tidak tahu apakah `T` bisa dibandingkan dengan `>`. Kode berikut sengaja gagal:

<RustPlayground
  code={`fn largest<T>(list: &[T]) -> &T {
    let mut largest = &list[0];

    for item in list {
        if item > largest {
            largest = item;
        }
    }

    largest
}

fn main() {
    let numbers = vec![34, 50, 25, 100, 65];
    println!("{}", largest(&numbers));
}`}
  expectError
  filename="src/main.rs"
  label="Contoh error generic tanpa trait bound"
/>

Pesan `binary operation > cannot be applied to type &T` dan saran `T: PartialOrd` menunjukkan bahwa generic tidak menghapus kebutuhan perilaku. Generic hanya menunda pemilihan tipe sampai pemanggilan.

## Struct generik

Struct juga bisa generik. `Point<T>` menyimpan dua nilai dengan tipe yang sama.

<RustPlayground
  code={`struct Point<T> {
    x: T,
    y: T,
}

fn main() {
    let integer = Point { x: 5, y: 10 };
    let float = Point { x: 1.0, y: 4.0 };

    println!("{} {}", integer.x, float.y);
}`}
  filename="src/main.rs"
  label="Struct Point generik"
/>

Kedua field memakai `T` yang sama, jadi `Point { x: 5, y: 4.0 }` gagal:

<RustPlayground
  code={`struct Point<T> {
    x: T,
    y: T,
}

fn main() {
    let salah = Point { x: 5, y: 4.0 };
    println!("{}", salah.x);
}`}
  expectError
  filename="src/main.rs"
  label="Contoh error tipe field tidak cocok"
/>

Kalau field boleh berbeda, gunakan dua parameter tipe:

<RustPlayground
  code={`struct Point<T, U> {
    x: T,
    y: U,
}

fn main() {
    let campuran = Point { x: 5, y: 4.0 };
    println!("{} {}", campuran.x, campuran.y);
}`}
  filename="src/main.rs"
  label="Struct dengan dua parameter tipe"
/>

## Method generik

Method bisa didefinisikan untuk semua `T` atau hanya untuk tipe tertentu.

<RustPlayground
  code={`struct Point<T> {
    x: T,
    y: T,
}

impl<T> Point<T> {
    fn x(&self) -> &T {
        &self.x
    }
}

fn main() {
    let p = Point { x: 5, y: 10 };
    println!("p.x = {}", p.x());
}`}
  filename="src/main.rs"
  label="Method pada impl generik"
/>

Kamu juga bisa menulis `impl Point<f32>` untuk method yang hanya berlaku pada `Point<f32>`. Ini berguna saat operasi membutuhkan kemampuan khusus tipe.

Method dengan parameter tipe sendiri bisa mencampur dua instance:

<RustPlayground
  code={`struct Point<X1, Y1> {
    x: X1,
    y: Y1,
}

impl<X1, Y1> Point<X1, Y1> {
    fn mixup<X2, Y2>(self, other: Point<X2, Y2>) -> Point<X1, Y2> {
        Point {
            x: self.x,
            y: other.y,
        }
    }
}

fn main() {
    let p1 = Point { x: 5, y: 10.4 };
    let p2 = Point { x: "Hello", y: 'c' };

    let p3 = p1.mixup(p2);
    println!("p3.x = {}, p3.y = {}", p3.x, p3.y);
}`}
  filename="src/main.rs"
  label="Method generik dengan tipe tambahan"
/>

## Monomorphization

Saat kompilasi, Rust membuat versi konkret untuk setiap tipe yang dipakai. Proses ini disebut monomorphization. Untuk `Point<i32>` dan `Point<f64>`, compiler menghasilkan kode untuk masing-masing tipe. Generic tidak meninggalkan dispatch runtime untuk kasus ini.

:::note[Kalau di bahasa lain]
TypeScript punya generic yang kuat, Go punya type parameter sejak versi 1.18, dan Python memakai type hint generic. PHP tidak punya generic native; dokumentasi PHPDoc sering dipakai sebagai pengganti. Rust memeriksa generic saat kompilasi dan membutuhkan trait bound untuk operasi seperti perbandingan.
:::

:::tip[Tips]
Tulis versi konkret dulu, lalu generalisasi ketika polanya jelas. Trait bound yang muncul dari kebutuhan kode lebih masuk akal daripada bound yang ditebak di awal.
:::
